## TL;DR

- Builds a 7-variant ablation chain for loop-model training (V1 non-shared+final-loss → V7 shared+per-step-loss+detach+instant-update+internal-truncation+gradient-checkpointing) and derives symbolic reverse-mode FLOPs and activation-memory formulas for each.
- `detach` cuts only the blue **temporal** gradient path — it does **not** remove local loss branches or parameter-gradient work, so it saves compute less than the diagram first suggests.
- Weight sharing collapses **parameter-side** memory (parameters + gradient buffers + optimizer state drop from $T$ copies to 1) but leaves **activation** memory at $T a_f + a_\ell$ — identical to the non-shared case.
- Only the **schedule change** (instant update, V5) turns outer-depth activation from linear-in-$T$ to $O(1)$ peak, because each optimizer step releases its interval's graph before the next step allocates anything.
- Toy benchmark (batch 32, $T_{\text{out}}=32$, $d_h=d_x=256$, inner depth $K=6$, Adam/CPU) empirically confirms the symbolic story across 10 measured rows.

## Why it matters

Training tricks for loop models (HRM, Geiping et al., Parcae, TRM) get conflated under the loose label "recurrence." This post disentangles them one knob at a time and produces a closed-form cost ledger — so practitioners can pick the right combination for their memory/compute budget instead of copying a recipe. Scope is explicitly cost, not accuracy.

## Section summaries

### §1 — Introduction

- Central question: "what does the loop cost during training?"
- Ingredients ablated: non-shared vs shared weights, terminal vs per-step losses, outer-step `detach`, instant update, internal truncation inside the cell, gradient checkpointing.
- Accuracy comparisons are deferred because "Different strategies change not only cost, but also the learning algorithm itself."
- Referenced prior work: Jolicoeur-Martineau (TRM) 2025, Geiping et al. 2025, Prairie et al. (Parcae) 2026, Zhu et al. 2025, Wang et al. (HRM) 2025.

### §2 — Setup and Measurement Contract

- Outer loop: $h_t = f_\theta(h_{t-1}, x_t)$, $t=1,\ldots,T$. Key Jacobians $J_t = \partial h_t/\partial h_{t-1}$ and $B_t = \partial h_t/\partial \theta_t$.
- Schedule split: V1–V4 share one end-of-rollout backward + one optimizer step; V5–V7 do one optimizer step per outer step ("instant update", used in HRM/TRM-style training).
- FLOPs primitives: $c_\ell$ (local loss bwd), $c_J = e_J + m_J$ (temporal Jacobian eval + product), $c_B = e_B + m_B$ (parameter Jacobian eval + product), $c_h$ (hidden-state grad add), $c_\theta$ (shared-grad accumulation), $c_u$ (optimizer update).
- Memory primitives: $a_f$ (one cell's activations), $a_\ell$ (one loss/head), $a_f^{\text{ckpt}}$ (checkpointed), $a_f^{\text{trunc}}$ (inner-truncated), $a_f^{\text{trunc,ckpt}}$ (both).
- Total memory: $M_{\text{total}} = M_{\text{act}} + M_{\text{param}} + M_{\text{grad}} + M_{\text{opt}}$. Formulas focus on $M_{\text{act}}$ because detach/ckpt/trunc primarily affect it.
- Parameter-side memory: non-shared $= T(p_\theta + p_g + p_{\text{opt}})$; shared $= p_\theta + p_g + p_{\text{opt}}$.
- Optimizer state sizes: SGD-no-momentum $p_{\text{opt}}=0$; momentum SGD ~1 extra tensor per param; Adam ~2 extra tensors per param.
- Figures: none referenced here.

### §3 — The Ablation Chain

One bullet per variant, with verbatim formulas:

- **V1 (non-shared + final loss).** Separate $\theta_t$ per step, one terminal loss $\ell_T$. $C = c_\ell + (T-1)c_J + Tc_B + Tc_u$; $M = T a_f + a_\ell$.
- **V2 (+ shared weights).** State recursion unchanged; step-local parameter terms fold into one shared buffer. $C = c_\ell + (T-1)c_J + Tc_B + (T-1)c_\theta + c_u$; $M = T a_f + a_\ell$. Weight tying still gives linear-time BPTT.
- **V3 (+ per-step losses).** Add $\ell_t$ at every step. Backward becomes $a_t = \delta_t + a_{t+1}J_{t+1}$. $C = Tc_\ell + (T-1)c_J + (T-1)c_h + Tc_B + (T-1)c_\theta + c_u = T C_{\text{local}} + (T-1) C_{\text{temporal}} - c_\theta + c_u$ with $C_{\text{local}} = c_\ell + c_B + c_\theta$, $C_{\text{temporal}} = c_J + c_h$. $M = T(a_f + a_\ell)$.
- **V4 (+ detach each step, end-of-rollout backward).** Cuts only blue temporal edges → $a_t = \delta_t$. $C = T c_\ell + T c_B + (T-1) c_\theta + c_u$. Savings vs V3 = $(T-1) C_{\text{temporal}}$. $M = T(\tilde a_f + \tilde a_\ell)$ — still linear in $T$ under end-of-rollout backward.
- **V5 (+ instant update).** Same detached graph but per-step optimizer.step(). Per optimizer interval: $C^{\text{interval}} = c_\ell + c_B + c_u$; over rollout $T(c_\ell + c_B + c_u)$. Peak: $M^{\text{peak}} = a_f + a_\ell$ (constant in $T$).
- **V6 (+ internal truncation inside the cell).** Truncate inner loop, only last refinement differentiable. $C^{\text{interval}} = c_\ell + c_B^{\text{trunc}} + c_u$ with $c_B^{\text{trunc}} \leq c_B$. $M^{\text{peak}} = a_f^{\text{trunc}} + a_\ell$, $a_f^{\text{trunc}} \leq a_f$. Anchors to HRM's one-step approximation.
- **V7 (+ gradient checkpointing).** Checkpoint the remaining differentiable part. $C^{\text{interval}} = c_\ell + c_B^{\text{trunc}} + c_u + r_{\text{ckpt}}^{\text{trunc}}$; $M^{\text{peak}} = a_f^{\text{trunc,ckpt}} + a_\ell$. Trades memory for recomputation FLOPs without changing the gradient graph.
- Figure used: **Fig 2** (huggin.png) in V2/V3 discussion — the Prelude/Recurrent/Coda diagram from Geiping et al. illustrating the "cleanest symbolic match" for shared-weight looped language models.
- Notable quote: *"`detach` removes the blue temporal path. It does **not** remove the gold local loss branches or the red parameter-gradient work."*

### §4 — Toy Experiment Check

- **Benchmark setup:** batch = 32, outer rollout $T_{\text{out}} = 32$, hidden size $d_h = 256$, input size $d_x = 256$, inner cell depth $K = 6$, Adam on CPU. Cell is $h_t = \tanh(W_h h_{t-1} + W_x x_t + b)$ with 6 internal refinement layers. V1 is untied (192 distinct refinement layers materialized); V2–V7 share one outer-step cell, so all execute 192 logical refinement calls.
- **FLOPs source:** `torch.profiler(with_flops=True)` wrapping the full optimizer-interval body — a comparative operator-accounted proxy, not hardware counters.
- **NFE:** Checkpointing does not change NFE (recomputation raises FLOPs but not logical forward count).
- Row convention: `↓` = main chain; `↳` = auxiliary variant modifying the preceding numbered row. Rows 1–4 measured per 32-step rollout; rows 5–7 per single outer step.
- **Three takeaways** (verbatim paraphrase):
  1. "Weight sharing collapses parameter-side memory, not activation memory." V1→V2 keeps activation peak at 66.09 MB but drops tracked peak from 451.85 MB to 69.10 MB.
  2. "Per-step losses make the local term dominant." V2→V3 raises FLOPs 4038→4428 M; V3→V4 only drops to 4298 M.
  3. "With per-step detach, streaming backward should be default." Streaming aux row keeps FLOPs ~same (4302 vs 4298 M) while cutting saved activations from 69 MB to 2.16 MB.

### §5 — Future Topics

- **Adaptive / routed recurrence.** Halting networks, mixture-of-recursions; NFE becomes input-dependent. Accounting must move from fixed $T$ to *expected* depth.
- **Systems work.** FSDP + compiler interactions; "communication, sharding boundaries, and recomputation matter just as much as local FLOPs and saved activations."

## Open questions / gaps

- No quantification of how much smaller $c_B^{\text{trunc}}$ and $a_f^{\text{trunc}}$ are than their non-truncated counterparts; only $\le$ is asserted.
- Claim that V2 is "the cleanest symbolic match" to Geiping / Parcae despite their added stochastic loop depth and outer-loop truncation is asserted, not derived.
- Rows 5–7 are stated to be normalized back to a 32-step horizon "when I want apples-to-apples" — the normalization is not shown.
